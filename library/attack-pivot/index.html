ATTACK EPISODE · PIVOT · FAILURE · TAKEOVER

趋势接管不是“反向出现一根大K”，而是原攻击者自己的关键Pivot被破坏。

Attack Pivot用于回答一个更具体的问题：上一段推动由谁控制？它最后一次成功组织推进的关键摆点在哪里？如果这个点被反向Break，原攻击段是否已经失败？

1. 识别Attack Episode

先定义一段连续推动：方向一致、存在有效结果，并且不是随机单根K线。

2. 找到攻击者Pivot

多头Attack中关注最后一个有效Higher Low；空头Attack中关注最后一个有效Lower High。这个点必须对后续推动有实际贡献。

3. 观察反向Break

反向价格真正破坏该Pivot，并出现位移/接受，比单纯吞没一根K更有结构意义。

4. 决定执行方式

激进方案可用Micro Break，稳妥方案可等待第一次Retest Hold；两者分别牺牲价格和确认度。

什么不算Attack Pivot

NOISE

区间中间的小摆点

如果这个摆点没有推动出新结果，被破坏也不代表控制权转移。

DECORATION

事后挑最好看的点

Pivot必须在当时就可定义，不能看到后续反转后再回头选一个最合适的位置。

SINGLE BAR

单根K线极值

除非它确实承担攻击结构功能，否则不能仅因为高/低明显就被定义为Pivot。

EA里应该保存什么

  • AttackEpisodeID
  • AttackDirection
  • PivotPrice / PivotTime / PivotTimeframe
  • PivotRole：推动前最后结构点
  • BreakTime / BreakClose / Displacement
  • RetestStatus
  • ReEntryPermission：同一Attack是否允许再次授权
