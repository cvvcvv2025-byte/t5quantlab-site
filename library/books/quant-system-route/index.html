Books / System & Quant Route
HYPOTHESIS → DATA → BACKTEST → AUDIT → FORWARD

从“我觉得这个规则有效”，走到“我能证明程序确实执行了这个规则”。

量化学习最容易走偏的地方，是过早学习复杂模型，却没有先学数据、过拟合、状态机和账户执行。T5的路线故意把工程审计放在模型复杂度之前。

Stage 1 · Perry Kaufman

建立系统交易地图：趋势、均值回归、波动、滤波、参数与评估。目标是知道有哪些方法，不是照抄某个系统。

Stage 2 · Ernest Chan

学习从研究想法到可回测策略的实际流程，包括数据、成本和实盘实现意识。

Stage 3 · Robert Pardo

重点补回测与优化：样本内/外、参数稳定性、过拟合和Walk-Forward思想。

Stage 4 · David Aronson

进一步挑战数据挖掘偏差和“看起来有效”的技术规则，建立Evidence-Based研究习惯。

T5研究流程

01 · SPEC

把想法写成规则

Entry、Exit、Risk、Display和必须保持不变的逻辑先冻结。

02 · TEST

先知道回测会怎么骗你

重绘、未来数据、成本、样本选择和参数拟合。

03 · PARITY

确认跨平台语义一致

时间、Bar、点差、数据源和订单模型不一致时，不比较结果。

04 · ACCOUNT

账户级审计

检查重复授权、订单失败、T1减仓、SL修改和重启恢复。

05 · EVIDENCE

把失败也记录

每个版本的样本、异常、淘汰理由都进入证据链。

06 · RELEASE

达到发布门槛再交付

代码能跑只是起点，文档、限制和验证都必须齐全。

最应该警惕的四件事

OVERFIT

参数越调越漂亮

如果每次亏损都增加一个过滤器，最终得到的可能只是历史解释器。

SEMANTIC DRIFT

代码和策略语义慢慢分叉

人工说的是“第一次Retest”，程序可能实现成“任意N根内触线”。必须做Parity。

STATE BUG

财务错误来自状态机

重复下单、重复减仓、重启后丢状态，可以摧毁一个理论上正确的策略。

DATA

数据差异被误认为策略变化

经纪商时区、报价、点差与Bar构造都可能让同一规则产生不同信号。

系统与量化研究内容用于软件与方法学习，不构成收益承诺。
