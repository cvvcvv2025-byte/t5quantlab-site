把“看起来会用”的指标，变成程序能执行的规则。

手工交易里一句“MACD重新走强”“布林带开始扩张”“RSI回到强势区”对人类够用，对EA不够。程序需要明确输入、状态、触发、失效、订单动作和恢复逻辑。

INPUT周期、参数、价格源、Session、数据源。

第一步：把自然语言改成可判定句子

手工说法程序仍然不知道什么需要冻结
MACD重新走强走强看线、柱子还是斜率？持续几根？Histogram连续N根增加 / Cross / 零轴条件
价格回踩EMA20Touch算不算？允许穿多少？收盘确认吗？距离阈值、穿越容忍、Close位置
布林带开始扩张BandWidth比什么更大？当前值、前值、滚动百分位或阈值
RSI出现背离哪个Swing？相隔多少根？必须创新低吗？Pivot定义、比较窗口、最小差异
趋势很强主观描述无法回测ADX、Slope、Structure或组合阈值

第二步：Signal不等于Entry

SIGNAL

指标事件

例如MACD Cross、RSI从30下方重新上穿、价格收回Bollinger中轨。

AUTHORIZATION

允许交易

Regime、Session、Spread、已有持仓、冷却期、方向过滤全部通过。

ENTRY

订单真正执行

当前收盘、下一根开盘、Limit回踩还是Stop突破必须写清。回测差异往往就藏在这里。

第三步：状态机比指标公式更容易出Bug

READY：没有未处理Signal，允许寻找新机会。
ARMED：指标条件满足，但还没到真正Entry。
ORDER_PENDING：订单已提交，必须等待真实结果。
OPEN：持仓存在，禁止同一Signal重复授权。
PROTECTED：Partial/BE已经执行，要记录动作是否成功。
CLOSED / COOLDOWN：退出后何时重新允许同方向Signal。
最危险的错误不是“MACD算错一位小数”，而是同一Cross重复下单、重启后忘记已有仓位、部分平仓失败却把状态改成成功。

四个指标策略规则化示例

MACD TREND

零轴 + 回撤 + 再扩张

Regime：H1 MACD>0。Location：价格回到EMA/结构区。Trigger：M5 Histogram从收缩转连续扩张。Invalidation：价格结构失效，不是MACD下一次Cross。

BOLLINGER RANGE

区间均值回归

Regime：ADX低、BandWidth非扩张。Location：外轨附近。Trigger：价格重新收回Band内。Target：中轨/对侧。强趋势时禁用。

RSI PULLBACK

趋势中的Range Shift

Regime：趋势多头。Signal：RSI回撤到强势区下沿而不是机械等30。Trigger：价格重新推进。Audit：不同RSI阈值是否稳定。

DONCHIAN BREAKOUT

突破 + ATR风险

Signal：N周期新高。Entry：Stop/Close/Next Open三者必须选一种。Risk：ATR归一化。State：同一突破不可重复授权。

第四步：回测必须和实盘语义一致

问题TradingView / 回测常见差异EA需要核对
Bar确认历史K线天然已收盘实盘是否只在新Bar处理一次
Bid / Ask图表常只展示一个价格流真实Entry/SL/TP用哪个价格
Spread固定或忽略波动时动态Spread
订单结果默认成交Rejected / Partial / Requote / Slippage
重启回测一次连续运行终端/VPS重启后状态恢复
多周期HTF值可能在历史中显得确定当前未收盘高周期Bar如何处理

第五步：每次改指标都要保留审计字段

time, symbol, timeframe, strategy_id regime, direction, indicator_values signal_id, signal_time, authorization_state entry_requested, entry_filled, fill_price, slippage sl, target1, target2, size partial_requested, partial_done, be_requested, be_done mfe, mae, exit_reason, realized_r version, parameter_set, data_source

没有这些字段，最后只能看到净利润，却无法回答：策略错了、参数错了、数据错了，还是程序执行错了。
