12 DRILLS · MT4 · MT5 · PINE · STATE · AUDIT

源码工程：能编译不等于语义没变。

这组题训练迁移、订单状态、重启、平台Parity和“该修还是该重构”的判断。

Q085 · MT4→MT5

把OrderSend替换成CTrade.Buy/Sell并编译通过，就算迁移完成吗？

答案

不算。还要处理Position/Order/Deal语义、账户模式、返回结果、部分平仓和状态恢复。

Q086 · NETTING

原MT4 EA依赖同品种多个独立ticket管理，迁移到MT5 Netting账户会有什么风险？

答案

同品种持仓可能合并为净头寸，原ticket级管理语义需要重构或限定Hedging模式。

Q087 · PINE SERIES

Pine的close[1]逐行翻成MQL数组[1]是否一定等价？

答案

不一定。必须确认数组方向、当前Bar与已收盘Bar语义，避免索引错位。

Q088 · SECURITY

TradingView request.security读取H1，MT5直接用当前未收盘H1值，可能造成什么？

答案

信号时序/重绘语义可能不同。需冻结母版使用已收盘还是实时HTF值。

Q089 · ORDER RESULT

EA发送部分平仓请求后立刻把T1Done=true，最大问题是什么？

答案

请求可能失败或实际成交量不同；状态必须以账户结果确认后推进。

Q090 · RESTART

EA重启后内存变量归零，但账户还有Runner，正确做法是什么？

答案

从真实持仓、订单注释/ID和持久化信息重建状态，不能当成全新会话。

Q091 · DUPLICATE

OnTick和OnTradeTransaction都可能推进同一状态，如何降低重复动作风险？

答案

明确单一状态所有者/幂等条件，并以唯一事件或当前账户状态防重复处理。

Q092 · PARITY

MT5比TV少5笔交易，第一步应调低阈值让数量一样吗？

答案

不应。先逐笔定位数据、时区、Bar Close、点差过滤或实现语义差异。

Q093 · REFACTOR

同一个Entry条件在4个函数复制了4份，新增一个过滤器应直接改4处吗？

答案

长期更适合先抽出统一规则入口，否则版本漂移和漏改风险会继续扩大。

Q094 · SECRET

源码里发现API Key硬编码，免费体检应该怎么处理？

答案

应提示敏感信息风险，不把密钥暴露到日志/分析结果，并建议改为Secret/环境配置。

Q095 · REWRITE

旧EA策略假设已被长期验证淘汰，但代码结构非常差，值得花时间重构吗？

答案

通常不值得。先区分工程问题和策略假设失败；无优势的主干不因重构变成好策略。

Q096 · CHANGE SCOPE

客户只要加邮件提醒，为什么仍要先识别Entry状态？

答案

否则可能把Sweep/观察状态也当正式Entry发邮件。小功能仍可能依赖核心状态语义。
