FROZEN RULE · PROBE · WAIT · MAIN ENTRY

Entry最终没有继续“优化”，而是冻结成三个状态。

研究目标从“找更多过滤器”转为“保证同一Attack只授权一次、状态跳转可复现、真实账户与图表显示一致”。

PROBE

早期试探

用于捕捉初始接管迹象，但风险和授权必须受控。Probe不是“猜底/猜顶”，它仍需要位置和最小结构事件。

WAIT

条件未闭合

当位置成立但接管不完整，系统明确进入等待，而不是为了提高出单率把半成品信号当正式Entry。

MAIN ENTRY

正式执行

关键执行条件闭合后授权主仓。此后同一Attack不得因为下一根K线再次满足相似条件而重复授权。

为什么停止继续优化Entry

条件继续增加会让历史看起来更干净

但每增加一个过滤器，都可能把真实前向的有效样本一起删掉，最终得到一个几乎不出单的漂亮模型。

真正的问题逐渐从“信号质量”转成“状态一致性”

同一Attack重复授权、止损后是否允许重新进入、Probe和Main Entry是否冲突，这些程序层问题比再加一个指标过滤更关键。

冻结规则才能做账户级复核

如果每看一批历史样本就改Entry，永远无法判断账户结果变化来自策略本身还是参数漂移。

程序必须保存的状态

状态字段用途
attack_id标识同一次攻击/结构事件，防止重复授权
entry_stateProbe / Wait / Main Entry / Invalidated
probe_used同一Attack是否已经使用过Probe额度
main_entry_used主仓是否已经授权
invalidated_at何时因失效位被取消
reentry_allowed止损后是否出现新的独立确认，避免机械重复进场

最危险的三个实现错误

DUPLICATE

每根K线重新判断授权

条件连续成立三根K线，就下三次单。这不是策略优势，是状态机缺失。

RESET

重启后忘记状态

EA重启或切图后把已授权Attack当成新事件，会制造重复订单。

REENTRY

止损即自动再进

没有新的Reclaim/Micro Break或独立Attack，仅因为原条件仍为true就重进，容易形成连续止损簇。
