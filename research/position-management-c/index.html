T1 PARTIAL · BREAKEVEN · RUNNER TO T2

C版管理的核心不是“保本”，而是把T1之后的持仓变成独立状态。

冻结语义：T1命中 → 减半 → 剩余仓位SL推保护 → Runner继续看T2。任何一步失败都必须记录，不能只看最终盈亏。

1. OPEN

订单成交后保存真实Entry、初始SL、T1、T2、仓位量和计划风险。

2. T1_TRIGGERED

价格首次触及T1后发起减仓。触及价格和减仓成交不是同一事件，两者都要记录。

3. PARTIAL_DONE

确认减仓实际成交后，才允许推进剩余仓位SL。

4. PROTECTED_RUNNER

Runner进入保护状态，继续等待T2或保护退出。这里开始，剩余仓位的结果要与前半仓分开计算。

5. CLOSED

记录T2、保本、结构退出、平台拒单后强制退出等原因。

为什么不用一句“T1后保本”代替

EXECUTION

减仓可能失败

最小手数、步进、市场状态、订单返回码都可能导致减仓失败。程序不能假设下指令=成交。

PROTECTION

改单可能被拒绝

保护位距离当前价太近、交易环境不同或价格快速穿越，都可能让SL修改失败。

ACCOUNTING

一笔交易其实有两段结果

前半仓已实现收益，Runner可能0R、T2或回吐。简单用“胜/负”会丢掉管理层信息。

审计时必须区分的结果

结果类型含义
T1 + T2减仓成功，Runner继续达到T2
T1 + BET1完成，Runner在保护位退出
T1 + Structural ExitT1完成后出现独立结构退出
T1 Triggered / Partial Failed价格到了，但减仓没有真实完成
Partial Done / BE Move Failed已减仓，但保护修改失败；风险暴露与策略假设不一致
SL Before T1完整初始止损
