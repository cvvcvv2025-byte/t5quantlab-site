Research Note 002 · Execution · State Machine

Reclaim 之后，什么时候才算真正 Takeover？

Micro Break 很早，Retest Hold 更稳。两者不是谁“更正确”，而是处在不同证据层级，应该对应不同的仓位与授权状态。

Micro Break 说明原攻击方第一次失去局部控制；Retest Hold 才证明新控制方有能力守住已经夺回的结构。

1. Reclaim 之后最容易犯的错误：把第一根反向推进当成趋势接管

价格重新收回关键区域后，第一段反向推进很容易让人产生“已经反转”的错觉。但在真实行情里，很多 Reclaim 只会形成短暂回抽，随后又被原趋势重新压回。

所以，我们不把 Reclaim 后出现一根强 K 线直接定义成 Takeover。需要继续观察它有没有破坏原攻击方真正依赖的微结构。

2. Micro Break 是最早可量化的接管证据

Micro Break 的定义不是随便突破一个很近的小高低点，而是反向推进打破了原攻击方向最近一次有效推进所形成的 pivot。这个 pivot 必须对原方向继续推动具有结构意义。

如果突破的只是噪声摆动点，那么算法会过早授权；如果 pivot 定得过远，又会把所有信号拖到行情已经走掉。

证据层级含义适合状态代价
Reclaim原突破暂未被接受Wait证据不足，不能直接主仓
Micro Break攻击方最近微结构被破坏Probe / 激进入场候选更早，但假接管更多
Retest Hold新结构第一次回踩守住Main Entry 候选更稳，但入场价格通常更差
Takeover Continuation新方向继续推进并扩展结构持仓/研究加仓标签需要避免追价和重复授权

3. 为什么我们把 Probe / Wait / Main Entry 分开

如果系统只有“有信号 / 没信号”两个状态，就会被迫在早进和晚进之间二选一。更合理的做法是承认证据会逐步增加：

  1. Wait：Reclaim 出现，但还没有结构破坏。
  2. Probe：Micro Break 已出现，允许用较低风险测试新方向是否成立。
  3. Main Entry：第一次 Retest Hold 完成，新方向不只突破，而且守住了控制权。

这样做的重点不是增加交易次数，而是让不同证据层级对应不同风险授权。

4. Retest Hold 为什么比单纯 Break 更重要

一个 Break 可以由单根冲动 K 线造成，但真正的结构接管通常需要证明“打过去以后还能守住”。第一次回踩正好提供这个验证窗口。

有效的 Retest Hold 不是要求价格一分不差碰某个水平，而是回踩后没有重新进入原攻击方有效控制区，并出现继续离开的反应。

5. 哪些情况不应该把 Micro Break 升级成 Main Entry

  • Break 后立即深度回到原攻击区，说明突破缺乏接受。
  • 回踩过程中吞没了 Micro Break 的起点结构，说明控制权并未稳定。
  • 高周期背景与当前位置强烈冲突，局部 Break 可能只是噪声。
  • 同一 Attack Episode 已经完成授权，不能因为连续小结构破位重复下单。

6. 对 EA 的直接影响

这套定义会落到状态机而不是“形态识别器”里。EA 需要记录当前 Attack Episode、最近有效 pivot、Reclaim 是否仍有效、Micro Break 是否已经授权、Retest 是否首次发生，以及同一结构是否已经被使用。

这样才能避免最常见的程序问题：重复下单、同一攻击段反复授权、Reclaim 失效后仍继续等待旧信号。

当前研究结论：Probe / Wait / Main Entry 的触发逻辑已冻结，不再为了美化历史结果继续收紧或放宽。后续重点转向账户级复核、状态冲突和前向验证。
