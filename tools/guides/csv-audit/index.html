EVENT LOG · STATE TRANSITION · FILL · MFE/MAE · VERSION

一个好CSV不是交易清单，而是能重建“当时系统为什么这么做”的事件日志。

只记录Entry、SL、TP和最终盈亏不够。状态机EA必须能回答：什么时候进入Wait、为什么授权Main Entry、T1是否真实减仓、SL为什么被修改、重启后状态有没有恢复。

四层字段

IDENTITY

身份字段

Timestamp、BrokerTime、Symbol、Timeframe、EA Version、Magic、Project/Setup/Attack ID。

PLAN

计划字段

Direction、Model、Grade、EntryLow/High、InitialSL、T1、T2、RiskR、Reason。

EXECUTION

执行字段

OrderID、FillPrice、Lot、Spread、SlippageEstimate、ErrorCode、成交/拒绝。

STATE

状态字段

PreviousState、NewState、T1Hit、PartialClose、BeforeSL、ProposedSL、AppliedSL、RunnerExit。

建议的最小事件类型

Event什么时候写为什么重要
SETUP_CREATED计划首次成立知道信号什么时候真正存在
STATE_CHANGEProbe/Wait/Main/Cancel变化重建状态机
ORDER_SENT提交订单区分信号与执行
ORDER_FILLED / REJECTED成交或拒绝统计真实执行质量
T1_HIT目标触发管理状态起点
PARTIAL_CLOSE减仓实际成交验证减半是否真的发生
SL_MODIFY每次止损变化发现SL回退/放宽
RUNNER_EXIT剩余仓位退出区分T1和Runner结果
SETUP_INVALIDATED计划失效避免旧计划残留

为什么需要 AttackEpisodeID / SetupID

如果系统只有时间和模型名，很难判断两笔相邻交易到底是两个独立机会，还是同一段行情被重复授权。唯一ID可以让你把多个状态、订单和管理动作串回同一个机会。

ATTACK

AttackEpisodeID

标识同一段攻击/推进过程，解决不同模型标签重复授权问题。

SETUP

SetupID

标识一份具体交易计划，包含Entry/SL/T1/T2和失效。

ORDER

Order / Position ID

标识券商执行层对象，不能和策略Setup混用。

MFE / MAE不要只在平仓后算一个数字

MFE（最大有利移动）和MAE（最大不利移动）可以帮助判断Entry质量和管理效率，但要和初始风险归一化，并明确统计窗口：入场→T1、入场→最终退出，还是整个Setup生命周期。

  • 记录MFE_R / MAE_R，而不仅是美元。
  • 区分T1前MFE和T1后Runner MFE。
  • 用真实FillPrice计算执行层MFE/MAE。
  • 不要用MFE反推“本来应该把TP放到最高点”。

一个CSV能不能用，做三个测试

REBUILD

能否重建时间线

不看图，只用CSV能否知道计划从产生到结束发生了什么？

COMPARE

能否对齐面板和账户

面板说T1完成时，CSV能否找到对应成交/管理动作？

DEBUG

能否定位异常

SL突然放宽、重复授权、订单拒绝时，能否找到具体状态和原因？
