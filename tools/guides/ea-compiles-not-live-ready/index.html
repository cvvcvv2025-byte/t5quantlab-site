COMPILE · ORDER · STATE · RESTART · AUDIT

0个编译错误只证明语法能通过，不证明EA能正确管理真钱账户。

真正危险的问题通常发生在运行期：重复下单、订单失败后状态仍推进、部分平仓没成交、SL修改被拒、重启后忘记已有仓位。

ORDER

请求是否真的成交

每次开仓、平仓、修改SL都必须检查返回结果和实际账户状态。

STATE

程序状态是否和账户一致

不能因为变量写成“T1Done=true”就假设部分平仓已经发生。

RESTART

重启能否恢复

终端重启、VPS重启或EA重新加载后，应从真实持仓重建管理状态。

门槛最低要求
Compile0 error，并处理关键warning
Order检查retcode/ticket/fill与实际volume
RiskSL不得回退，最小手数/步长/StopLevel兼容
State同一Attack去重、T1/BE/Runner状态可追踪
Restart重新加载后不重复授权、不丢管理状态
AuditCSV/日志能重建每一步动作
账户级审计清单发布前检查表
正式资金前应在目标经纪商环境进行编译、模拟、审计与前向验证。
