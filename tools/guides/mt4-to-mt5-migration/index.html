Guides / MT4→MT5
ORDER MODEL · POSITION · DEAL · HANDLE · COPYBUFFER

MT4→MT5不是把函数名替换一遍。

真正要迁移的是交易语义：订单、持仓、成交、指标数据、账户模式、状态恢复和错误处理。逐行翻译最容易制造“能编译但行为变了”的版本。

层MT4常见思路MT5迁移重点
TradingOrderSend/OrderSelect围绕订单区分Orders、Positions、Deals；可使用CTrade但仍要检查结果
Account Mode常按ticket管理多单必须确认Hedging/Netting；同品种持仓语义不同
Indicators很多iMA/iATR直接返回值常先获得handle，再CopyBuffer读取数据
Events主要依赖OnTick与订单轮询可利用OnTradeTransaction，但要避免和OnTick状态重复处理
SymbolMarketInfo等SymbolInfo*、volume step、digits、stops level重新核对

迁移正确标准不是“信号看起来差不多”

  • 同一历史输入下，关键Context/Entry语义可以逐笔解释
  • SL/T1/T2价格计算规则一致
  • 部分平仓和Runner管理在目标账户模式可执行
  • 重复授权/同一Attack去重一致
  • 重启恢复后行为一致
  • 差异必须归因于数据/平台，而不是静默改变规则
平台Parity免费源码体检为什么能编译还不够
平台迁移必须在目标MT5账户模式和经纪商规则下重新审计。
