PINE EDITOR · VERSION · ALERT · INVITE-ONLY

TradingView脚本更新最容易犯的错，是“新代码覆盖了，但图表还在跑旧实例”。

源码保存、编译、Add to chart、报警重建和邀请制权限是不同步骤。每次版本更新都应该能确认“当前图表到底运行哪一版”。

源码脚本安装

1. 打开 Pine Editor

在TradingView图表下方进入Pine Editor，新建脚本或打开已有脚本。

2. 粘贴完整源码

不要只替换某个函数片段，除非你确认依赖关系。保存前检查Pine版本声明。

3. 保存并编译

处理所有编译错误。Warning或性能提示也应记录，尤其是多周期request.security与大量历史循环。

4. Add to chart

保存成功不代表图表实例已更新。必要时先删除旧实例，再把当前脚本重新添加到图表。

5. 检查版本号

建议在标题或面板明确显示版本号，以便截图和审计时知道正在跑哪一版。

更新后为什么信号看起来没变

OLD INSTANCE

图上仍是旧实例

编辑器代码已更新，但图表没有重新加载。

INPUT

旧参数被保留

更新脚本后，图表实例可能继续使用此前保存的输入参数。

ALERT

旧Alert仍引用旧逻辑

TradingView报警通常在创建时冻结条件。重大逻辑更新后应重新建立Alert。

TIMEFRAME

只显示当前周期

如果脚本有周期过滤，换图后不一定会显示其他周期计划。

HISTORY

历史状态被重算

脚本改动、数据修订和request.security行为都可能让历史图看起来与此前截图不同。

LIMIT

账户脚本/指标数量限制

不同TradingView计划的图表指标数量和功能限制不同，不能假设所有用户环境一致。

邀请制脚本 / 授权版

如果脚本使用TradingView Invite-only发布，用户不需要拿到源码，而是由发布者给指定TradingView用户名开访问权限。授权脚本和源码交付是两种不同产品形态。

方式用户拿到什么适合
源码完整Pine代码用户需要自行修改/审计
Protected可使用但看不到源码公开发布且保护实现
Invite-only按用户名授权访问订阅/租用型交付

每次版本更新都记录这6项

  • 版本号与发布日期。
  • 改了什么。
  • 明确没改什么。
  • 是否影响历史信号。
  • 是否需要重建Alert。
  • 是否需要删除旧实例后重新加载。
Pine源码免费体检源码修改审计
TradingView脚本的可用功能受账户计划和平台规则影响，版本交付应明确说明环境要求。
