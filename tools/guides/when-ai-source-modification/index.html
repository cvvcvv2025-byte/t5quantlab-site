REPAIR · EXTEND · MIGRATE · REWRITE

有源码，不代表第一步就应该重写。

如果原程序已经包含大量经过验证的Entry、Risk、状态和显示逻辑，最安全的路线通常是先重建现有语义，再冻结本次修改范围。

免费本地源码体检
适合修改

主干仍可解释

能定位Entry/Exit/Risk/State，编译基础正常，需求是修Bug、加提醒、加CSV、改显示或有限迁移。

更适合重构/重写

主干已不可维护

大量全局变量互相覆盖、逻辑复制多份、状态靠隐式条件推断、历史版本补丁互相冲突。

AI真正该解决的不是“生成代码”，而是保持不该变的东西不变

  • 重建当前Entry / Exit / Risk / State
  • 列出本次Changed Scope
  • 列出必须Unchanged的冻结逻辑
  • 指出依赖、冲突和潜在副作用
  • 生成完整源码而不是零散补丁
  • 提供CHANGELOG并重新编译/审计
