T5 Quant Lab / Verification / Audit Checklist
SIGNAL · EXECUTION · STATE · MANAGEMENT · DATA · RECOVERY

EA“能编译”只是最低门槛。真正要审计的是整个账户状态。

很多策略回测看起来正常，进入真实账户后却因为重复授权、改单失败、重启丢状态、未成交也计入统计而失真。下面是一份进入前向前的最小审计清单。

1. Signal / Authorization

检查项通过标准
同一结构重复信号同一attack_id只能按规则授权一次，除非形成新的独立再确认
未来函数 / 重绘信号只使用当时可见数据，历史回看不改变已完成信号
周期切换切换图表周期不产生额外授权或改变高周期状态
Bar内多次触发明确按tick、收盘或首次触发处理，不能无意重复

2. Execution / Broker

SPREAD

点差过滤

实际使用SymbolInfo/平台返回值，而不是假设固定点差；过滤失败必须有日志。

ORDER RESULT

订单返回码

发单、改单、减仓、平仓都要确认真实结果。调用成功不等于成交成功。

PRICE / VOLUME

价格与手数规范化

Tick Size、Digits、Volume Step、Min/Max Volume必须适配不同经纪商。

3. Position State

状态需要验证
Pending Plan计划未成交时不得当作持仓统计
Open真实成交价、真实手数、SL/TP与内部状态一致
T1 Triggered触价与减仓成交分开记录
ProtectedSL实际修改成功后才更新状态
Runner剩余手数、目标和保护退出独立记录
Closed退出原因唯一且可追溯

4. Restart / Recovery

EA重启

从真实账户仓位恢复状态，而不是从初始状态重新开始。

MT5/MT4断线重连

重连后重新核对订单、持仓、SL/TP和已完成管理动作。

图表关闭再打开

不能因为重新OnInit就把旧Attack重新授权。

异常成交

部分成交、拒单、价格跳空时进入明确异常状态，不允许悄悄继续。

5. CSV / Audit Data

没有可复现字段，就没有真正的账户复核。

建议最小字段：timestamp、symbol、timeframe、version、attack_id、signal_type、direction、planned_entry、actual_entry、initial_sl、T1、T2、planned_risk、volume、filled、T1_hit、partial_close、BE_move、runner_exit、MFE、MAE、spread、result_R、error_code。

审计清单的目标不是让EA“看起来专业”，而是让任何异常都能定位到具体状态、订单或数据字段。无法复现的盈利结果不应进入正式发布判断。
