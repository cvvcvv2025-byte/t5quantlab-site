DATA SOURCE · TIMEZONE · SPREAD · SYMBOL · EXECUTION

同一个策略在TradingView、MT5和不同经纪商上结果不同，不一定是代码错，也可能是数据根本不同。

Parity审计的任务不是强迫所有平台得到完全一样的K线，而是确认差异来自哪里，以及这些差异是否足以改变信号和财务结果。

最常见的六类差异

SESSION

服务器时区

UTC+0、UTC+2/3、UTC+8会改变H1/H4甚至日线切分，结构高低点也会随之改变。

FEED

报价源

现货黄金、经纪商CFD、COMEX GC不是同一产品；高低点、成交量和假突破都可能不同。

SPREAD

Bid / Ask 与图表Mid

图上看似没有触及SL，真实Ask/Bid可能已经成交。回测若只用单一OHLC会低估执行差异。

BAR BUILD

K线构建

缺失tick、历史补齐和交易时段差异会导致同周期K线形态不同。

SYMBOL RULES

Digits / Tick Size

XAUUSD、XAUUSDc、GOLD等合约规格不同，价格和手数规范化必须单独适配。

VOLUME

成交量含义

MT平台常见Tick Volume，期货是集中市场成交量。不能把两者当完全相同的数据解释。

Parity不等于“每一笔完全相同”

真正需要一致的是规则语义。

层级目标
Structure Parity相同定义下，高低点、BOS/CHOCH和关键AOI是否在可解释范围内一致
Signal Parity同一历史片段里，触发事件是否同方向、同类型；差异是否来自K线边界
Risk Parity失效位、风险金额、手数换算是否保持相同语义
Management ParityT1、减仓、保本、Runner状态是否按同一顺序执行
Financial Parity允许因点差和报价有差异，但整体统计不能因实现错误完全偏离

建议的对比流程

固定10–30个关键案例

包含正常盈利、止损、临界触发、极窄SL、跨时区边界和重复授权风险。

逐案例截取同一时间段

记录TV时间、MT服务器时间、价格差、spread和符号规格。

先比状态，再比结果

如果Entry状态都不同，先解决算法或K线差异，不要直接比较净利润。

最后做账户级统计

只有状态和订单路径一致后，PF、Expectancy、回撤等财务指标才有比较意义。

什么时候必须判定“不是同一策略”

LOGIC DRIFT

MT版偷偷换了算法

例如Pine用收盘确认，MT用tick内即时触发；这不是数据差异，而是实现语义不同。

STATE DRIFT

管理动作顺序不同

一端T1后先减仓再保本，另一端先改单再减仓，异常行情下结果可能完全不同。

FILTER DRIFT

过滤器口径不同

点差、时间、最小SL、ATR等任何一个口径不同，都应单独记录版本差异。

账户审计清单Entry状态机源码审计指南
平台结果不一致时，第一反应不应是“哪个平台错了”，而应拆成数据、时区、执行和代码语义四层逐项定位。
